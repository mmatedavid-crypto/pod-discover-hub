# search-hybrid rules

- Search recency words ("mostanában", "a héten", "idén") are detected only by `_shared/search-temporal.ts`; `search-hybrid` then adds bounded in-window candidates from `search_episodes_recent_v1` (service-role only, published-date index first) and keeps in-window episodes ahead after every rerank, because the all-time candidate pools rarely contain recent episodes for broad topics.
- In `search-hybrid`, people/organization/topic catalog anchors count only on whole-word matches and a show is hard-pinned only when the query is its name (`_shared/search-podcast-pin.ts`); partial show-title matches join the candidates unpinned, because prefix/infix matches (AI → Airbag, alma → Almási) hijacked topic searches.
- Sentence-like searches (question, request opener, ≥4 subject words) take the complex path in `search-hybrid` only via `_shared/search-complex.ts` (AI concepts, meaning-first weights, final AI check of public metadata, off-topic dropped, honest empty `no_relevant_results`); names, show titles, name-only queries, tickers and bots never do, and the check model must differ from the `search-quality-eval` judge, because simple searches already work and a verifier equal to the judge would inflate the measurement. Owner switches: `app_settings.search_engine.complex_search_enabled` / `complex_verify_enabled` / `verify_model`.
- `search-hybrid` completes unknown words only to catalog words (`complete_unknown_tokens_v1`) and an exact person name inside a longer query is an unpinned anchor (`_shared/search-name-windows.ts`), because completions or embedded names must never invent results or hijack the query.
