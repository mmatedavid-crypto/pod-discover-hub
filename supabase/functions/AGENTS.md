# Edge function rules (clean-text repair queue)

- Rewrite existing clean text from RSS only via `_shared/clean-text-rss-repair.ts` plans, reviewed (`clean-text-repair` `rss_*`, ≤50 ids) or unattended in `clean-text-repair-queue` (lease/finite statuses, gate in `_shared/clean-text-repair-queue.ts`, `apply_clean_text_repair_v1` backup + CAS, verify/rollback, daily cap); legacy ytdesc rows only via `_shared/clean-text-legacy-ytdesc.ts` (hash provenance + identity checks, ambiguous → `needs_review`) in the queue's `legacy` lane with its own cap, because unreviewed rewrites can drop names or add promo and backed-up/other-source text must never be overwritten.
- Resolve legacy ytdesc review rows only via `_shared/clean-text-legacy-resolve.ts` in `clean-text-repair-queue` admin actions (merge only for v3-confirmed videos, extract-only, internal-only `multi_source`/`youtube_corroborated` source types, outcomes logged in `clean_text_legacy_resolutions`, AI only through the reserved/capped `clean_text_legacy_ai_reviews` ledger), because merged or unconfirmed third-party text must never become public and every decision must stay reversible.
- Astra review of clean-text rows waiting for a human runs only as the advisory `clean-text-repair-queue` `astra_review` action (policy in `_shared/clean-text-astra-review.ts`, atomic reserve/settle against `clean_text_astra_review_controls` caps, results in `clean_text_astra_reviews`); it never writes episode text or queue status, because text changes must stay on the reviewed backup + CAS apply paths.
- Feed reads go through `_shared/fetch-one.ts` with item order/identity rules in `_shared/feed-item-policy.ts` (newest first before the cap; a `<link>` counts as episode identity only without a guid and when unique in the feed), and `incremental-refresh` retries failed feeds whose backoff has passed (bounded share per run), because oldest-first feeds, shared show-page links and a never-cleared `next_fetch_at` silently froze hundreds of podcasts.
- Free Wikipedia matching for people/organizations runs only through `wiki-safe-matcher` with policy in `_shared/wiki-safe-match.ts` (exact huwiki article, Wikidata human/type class, context words from accepted links only, date sanity, no same-name or ambiguous identities) and writes only via `apply_wiki_safe_match_v1` (unmatched rows only, before-state in `wiki_safe_match_log`, undo `revert_wiki_safe_match_v1`); everything else is logged for review, because name-only matches picked homonyms, cities and devices.
- Permanent foreign-show deletion runs only through `language-cleanup-runner` with `block_feed: true` (service role, internal token or admin JWT): the feed goes into `podcast_feed_blocklist` before deletion and a BEFORE INSERT trigger on `podcasts` silently skips blocked feeds; decide deletion only when the text check and an independent AI/raw-feed check agree, because single-opinion AI verdicts deleted real Hungarian shows before and a blocked feed never comes back.
- Second-opinion (escalation) person reviews claim only via `claim_person_openai_escalation_pairs` and write only via `apply_person_openai_escalation_item` (same source hash as the primary, separate lane cap in `reserve_person_openai_batch_cost`, rejection only when both reviews reject and the escalation quotes the source; mirror in `escalationFinal`), because a single AI opinion must never close a link.
- Primary person batch claims read eligible pairs from `person_openai_batch_candidate_pool` (refreshed hourly by `refresh_person_openai_batch_candidate_pool_v1` via pg_cron) and re-check pending/decided/manual/lease/language live per pair; never sort the full pending mention set inside a request, because that exceeded the 8s request timeout and aborted batches.
