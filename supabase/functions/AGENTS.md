# Edge function rules (clean-text repair queue)

- Rewrite existing clean text from RSS only via `_shared/clean-text-rss-repair.ts` plans, reviewed (`clean-text-repair` `rss_*`, ≤50 ids) or unattended in `clean-text-repair-queue` (lease/finite statuses, gate in `_shared/clean-text-repair-queue.ts`, `apply_clean_text_repair_v1` backup + CAS, verify/rollback, daily cap); legacy ytdesc rows only via `_shared/clean-text-legacy-ytdesc.ts` (hash provenance + identity checks, ambiguous → `needs_review`) in the queue's `legacy` lane with its own cap, because unreviewed rewrites can drop names or add promo and backed-up/other-source text must never be overwritten.
- Feed reads go through `_shared/fetch-one.ts` with item order/identity rules in `_shared/feed-item-policy.ts` (newest first before the cap; a `<link>` counts as episode identity only without a guid and when unique in the feed), and `incremental-refresh` retries failed feeds whose backoff has passed (bounded share per run), because oldest-first feeds, shared show-page links and a never-cleared `next_fetch_at` silently froze hundreds of podcasts.
- Free Wikipedia matching for people/organizations runs only through `wiki-safe-matcher` with policy in `_shared/wiki-safe-match.ts` (exact huwiki article, Wikidata human/type class, context words from accepted links only, date sanity, no same-name or ambiguous identities) and writes only via `apply_wiki_safe_match_v1` (unmatched rows only, before-state in `wiki_safe_match_log`, undo `revert_wiki_safe_match_v1`); everything else is logged for review, because name-only matches picked homonyms, cities and devices.
- Permanent foreign-show deletion runs only through `language-cleanup-runner` with `block_feed: true` (service role, internal token or admin JWT): the feed goes into `podcast_feed_blocklist` before deletion and a BEFORE INSERT trigger on `podcasts` silently skips blocked feeds; decide deletion only when the text check and an independent AI/raw-feed check agree, because single-opinion AI verdicts deleted real Hungarian shows before and a blocked feed never comes back.
- Second-opinion (escalation) person reviews claim only via `claim_person_openai_escalation_pairs` and write only via `apply_person_openai_escalation_item` (same source hash as the primary, separate lane cap in `reserve_person_openai_batch_cost`, rejection only when both reviews reject and the escalation quotes the source; mirror in `escalationFinal`), because a single AI opinion must never close a link.
- Search and recommendation quality is judged only by `search-quality-eval` (policy in `_shared/search-quality-eval.ts`: real visitor search path via the agent key, cheap judge + stronger calibration sample, ~30% deterministic holdout, spend reserved per call against the run cap); a ranking change stays live only if the whole set improves and no query type regresses on the holdout, because single-query fixes hid global regressions.
- `similar_episodes` / `get_related_episodes_by_embedding` keep the default HNSW scan and run the bounded other-show fallback (iterative scan, ≤4,000 tuples, no chunks) only when the normal lookup is empty; never enable iterative scan on the normal path, because it pushed lookups past the 8s statement timeout.
- When the AI provider refuses for balance/rate reasons (HTTP 402/429 or the open `ai_credit_breaker`), runners hand the work back as pending with the attempt refunded and stop the run; they never mark it failed/blocked or add a backoff entry, because a 3-day credit outage (Nov 2026) otherwise left hundreds of fresh episodes blocked or postponed for a week. Podcast lists read through the API must be paged (≤1,000 rows per request).
- Feed `health_state` `rss_url_not_found`/`needs_manual_rss_review` is cleared only by the `podcasts_clear_stale_feed_health` trigger on a clean fetch (old state in `health_recovered`), never by runners, because stale outage marks silently dropped live shows from SEO, hydration, sitemap and ranking.
- External OpenAI spend (person batch, entity descriptions, evidence pilot) is charged only through `external_ai_budget_charge_v1` via the job-table budget triggers (`external_ai_budget_ledger`, fail-closed without an active `external_ai_budget_grants` row; old lanes limited to the grant's legacy cap; evidence pilot to the pilot cap; evidence bulk only after a `passed` row in `person_evidence_gate_runs`), because per-lane caps alone double-counted and could not see open reservations across pipelines.
- Search Console totals come only from `gsc_site_daily` (dimension `date`, Google's site total incl. anonymised queries, final vs partial from `firstIncompleteDate`), written by `gsc-weekly-insights` `sync` (daily, no AI/email; per-day query+page detail paged with `startRow`); never sum top-N query/page rows as a site total, because query rows covered only ~16% of clicks.
- Person pages, prerender, counts and sitemap read episodes only from `person_public_episode_links_v1` via `get_person_page_episodes_v1` (counts refreshed hourly by `refresh_person_episode_counts_v1`; 0 episodes keeps the page, noindex only when also no verified bio and no search traffic), because separate rules made counters, lists and crawler HTML disagree.
- Show-host inheritance lives only in `person_host_rules` (podcast + person/scoped alias → canonical, optional valid_from/until or sub-show title_pattern, source URL+quote+hash, owner_confirmed only for owner statements) applied by `apply_person_host_rules_v1` / insert triggers into `resolved_show_host` with `person_host_rule_resolutions` + `undo_person_host_rule_pairs_v1`; never a blanket rule on collection channels, never over explicit decisions or episode-text contradictions, and `person_public_episode_links_v1` excludes it (roles via `person_show_host_roles_v1`), because series hosts must not be re-judged by AI nor counted as spoken appearances. Tests: `supabase/tests/person_show_host_rules.sql`.
- Free person source lanes (`person-source-lanes`: deterministic role labels `_shared/person-role-label.ts` + public episode page meta) accept only explicit multi-token label hits with an independent identity anchor and audit every write in `person_pair_lane_audit`, because name equality or LLM scores are not identity proof.
- Explicit episode credits (named narrator/preacher/performer/guest/🗣️ speaker in the publisher's episode text) live only in `person_episode_credit_rules` (per show, optional sub-show title, non-greedy-first credit regex because the first quantifier sets PostgreSQL RE greediness) and are applied by `apply_person_episode_credit_rules_v1` / the insert trigger with before-state in `person_episode_credit_resolutions` and `undo_person_episode_credit_pairs_v1`; a credited person is accepted only with a show-anchored identity, and the lane never closes a pair as absent (no `resolved_feed_credit_not_episode` outcome), because omission or another named speaker does not prove absence. Admin summary: `get_person_rule_lanes_status_v1`.
- Person identity merges run only through `person_identity_merge_rules` (one hop, validated against chains/cycles and `person_identity_separation_rules`) and Hungarian name-form rules in `person_name_variant_rules`/`_forms` (global or context-checked); the `a_canonicalize_*`/`b_canonicalize_name_*` triggers redirect new rows to the canonical person keeping the stronger decision, merged profiles stay hidden, and every run keeps full row backups in `person_identity_repair_backup`, because homonyms must never be merged by name alone and merges must stay reversible. Admin summary: `get_person_identity_status_v1`.
