# Project architecture rules

- Gate bulk relationship and Astra work through the shared processing-priority check before claiming or paid work, and bound request overrides by stored controls, because backlog size must not displace visitor-facing maintenance.

- Resolve person and organization chip linkability through `get_linkable_entities` in one batched request, because per-card or per-kind reads slow search result rendering.
- Background runners must re-read shared control state before persisting telemetry, because an in-flight whole-object write can undo an external pause.
- Serve episode Q&A pilot content only through `episode_answers_public` / `topic_episode_answers`, because the base table holds private transcript excerpts that must never reach the browser.
- Page and player telemetry must use `getAnalyticsSessionId` for one anonymous tab-scoped ID, because separate IDs prevent reliable landing-to-listening attribution; historical events must not be rewritten or treated as cross-session returning listeners.
- Visitor episode lists sorted newest-first must match an existing episodes index sort order (including NULLS LAST), because an unmatched sort reads the whole episodes table and times out under background load.
- Emit NewsArticle and Google News sitemap entries only for published, live Podiverzum Heti editorial articles (via `_shared/heti-editorial.ts`), never for podcast catalog pages or hubs, and never name the site publisher as publisher of third-party podcasts, because RSS show notes are not original journalism.
- Person name search must resolve exact catalog names and indexed person links before any text scan, rank accepted participant > subject > mention > text-verified pending > text-only via `_shared/search-person-evidence.ts`, and never pin or merge an ambiguous or same-name identity, because synchronous ILIKE scans timed out and homonyms must not be asserted as one person.
- Bulk person–episode relevance review runs only through `person-relevance-openai-batch` with policy in `_shared/person-relevance-openai-batch.ts` and the `*_person_openai_batch_*` RPCs (lease, cost reservation, audited apply, rollback), because 24h async batches need durable leases, hard spend caps and reversible, protected writes.

- Quoted search queries ("..." / „...”) run only the exact-phrase branch in `search-hybrid` via `_shared/search-exact-phrase.ts` (indexed search_tsv + clean-text FTS, every hit re-verified, no synonyms/embeddings/rerank), because Google-style quotes must never return non-exact matches.
- The best-text-source runner reads change feeds in bounded batches (≤60 episodes per call, no transcript `segments` column, long texts previewed from a prefix) and rewrites done clean text only through the verified-YouTube re-clean in `_shared/best-text-source-core.ts` (informative-gain gate in `_shared/youtube-source-gain.ts`, daily cap, `apply_clean_text_repair_v1` backup + CAS), because larger batches exceed edge CPU limits and source changes must not trigger unreviewed or irreversible corpus rewrites.
- Write `episode_youtube_links` only through `upsert_episode_youtube_links_v1` (change-only, row-locked, confirmed links sticky unless the same scan picks another video, manual/human links untouched); its `updated_at` means a real content/match change and observation-only fields use `metadata_refreshed_at`; downstream reprocessing is driven by `episode_source_change_queue` (trigger + lease/`change_seq` ack via `claim_/ack_episode_source_changes_v1`), because no-op rescans churned the change feed and buried new pairs behind thousands of fake events.
- Spotify episode descriptions are a clean-text source only via `_shared/spotify-source-gain.ts` (episode and show match ≥0.8, publisher show notes that keep every RSS fact or replace an empty RSS, removal-only promo/CTA stripping with Unicode-safe boundaries) and ranked below verified articles/YouTube; automatic Spotify re-cleans apply only to best-source rows whose recorded evidence is a verified `spotify_better` selection, never over reviewed canary batches or YouTube-derived text, and `episode_spotify_meta` has no anon/authenticated access; Spotify text and the server-only transcript lexical index (`episode_transcript_lexical_chunks`, tokens + offsets, no text) are internal processing only, because Spotify data and index-only transcripts are not cleared for public display.
- Rewrite existing clean text from RSS only via `clean-text-repair` `rss_*` actions and `_shared/clean-text-rss-repair.ts` (reviewed ids ≤50, backup + CAS, no overwrite of backed-up/other-source text, name/timecode and show-boilerplate gates), because unreviewed rewrites can drop names or add channel promo.
