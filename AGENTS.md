# Project architecture rules

Subdirectories may have their own `AGENTS.md` (e.g. `supabase/functions/`); read it before changing files there.

- Gate bulk relationship and Astra work through the shared processing-priority check before claiming or paid work, and bound request overrides by stored controls, because backlog size must not displace visitor-facing maintenance; jobs listed in `EXTERNAL_API_JOBS` / `OWNER_GATE_EXEMPT_JOBS` (owner decisions: dedicated external API, Astra jobs nothing waits on) bypass only the visitor-queue gate, never their cost caps or acceptance policy.

- Resolve person and organization chip linkability through `get_linkable_entities` in one batched request, because per-card or per-kind reads slow search result rendering.
- Background runners must re-read shared control state before persisting telemetry, because an in-flight whole-object write can undo an external pause.
- Serve episode Q&A pilot content only through `episode_answers_public` / `topic_episode_answers`, because the base table holds private transcript excerpts that must never reach the browser.
- Page and player telemetry must use `getAnalyticsSessionId` for one anonymous tab-scoped ID, because separate IDs prevent reliable landing-to-listening attribution; historical events must not be rewritten or treated as cross-session returning listeners.
- Visitor episode lists sorted newest-first must match an existing episodes index sort order (including NULLS LAST), because an unmatched sort reads the whole episodes table and times out under background load.
- Emit NewsArticle and Google News sitemap entries only for published, live Podiverzum Heti editorial articles (via `_shared/heti-editorial.ts`), never for podcast catalog pages or hubs, and never name the site publisher as publisher of third-party podcasts, because RSS show notes are not original journalism.
- Person name search must resolve exact catalog names and indexed person links before any text scan, rank accepted participant > subject > mention > text-verified pending > text-only via `_shared/search-person-evidence.ts`, and never pin or merge an ambiguous or same-name identity, because synchronous ILIKE scans timed out and homonyms must not be asserted as one person.
- Bulk person–episode relevance review runs only through `person-relevance-openai-batch` with policy in `_shared/person-relevance-openai-batch.ts` and the `*_person_openai_batch_*` RPCs (lease, cost reservation, audited apply, rollback), because 24h async batches need durable leases, hard spend caps and reversible, protected writes.

- Quoted search queries ("..." / „...”) run only the exact-phrase branch in `search-hybrid` via `_shared/search-exact-phrase.ts` (indexed search_tsv + clean-text FTS, every hit re-verified, no synonyms/embeddings/rerank), because Google-style quotes must never return non-exact matches.
- The best-text-source runner reads change feeds in bounded batches (≤60 episodes per call, no transcript `segments` column, long texts previewed from a prefix) and rewrites done clean text only through the verified-YouTube re-clean in `_shared/best-text-source-core.ts` (informative-gain gate in `_shared/youtube-source-gain.ts`, daily cap, `apply_clean_text_repair_v1` backup + CAS), because larger batches exceed edge CPU limits and source changes must not trigger unreviewed or irreversible corpus rewrites.
- Write `episode_youtube_links` only through `upsert_episode_youtube_links_v1` (change-only, row-locked, confirmed links sticky unless the same scan picks another video, manual/human links untouched); its `updated_at` means a real content/match change and observation-only fields use `metadata_refreshed_at`; downstream reprocessing is driven by `episode_source_change_queue` (trigger + lease/`change_seq` ack via `claim_/ack_episode_source_changes_v1`), because no-op rescans churned the change feed and buried new pairs behind thousands of fake events.
- Spotify descriptions feed clean text only via `_shared/spotify-source-gain.ts` (episode+show match ≥0.8, keep every RSS fact, removal-only promo stripping), ranked below articles/YouTube; auto re-cleans only for verified `spotify_better` rows, never over reviewed canaries or YouTube text; `episode_spotify_meta` and the transcript lexical index stay server-only, because raw metadata and transcripts are not cleared for display.
- Public pages read cleaned text only via `get_episode_public_clean_description_v2` (sources allowlisted in `app_settings.public_clean_text_display`, never transcript, source label + link), because the owner must be able to switch a source off without a deploy.
- Persist derived episode results (SEO / entity / topic) only through `apply_episode_seo_result_v1` / `apply_episode_entities_v1` / `apply_episode_topics_v1`, recording the exact clean-text hash read with the input (`get_episode_derivation_inputs_v1`, or a job's recorded `input_provenance` via `_shared/derivation-state.ts`), never a version inferred from prompt text, because the write and its freshness mark must serialize against clean-text updates and an older result must never overwrite a newer one or be marked current.
- Background runners log start/finish through `_shared/runner-run-log.ts` into `pipeline_runner_runs`, and `get_pipeline_health_snapshot_v1` judges health from those completions, never from cron dispatch success, because a killed worker still shows a succeeded cron run.
- `person-entity-extractor` skips episodes whose input fingerprint (`_shared/person-extractor-fingerprint.ts`) is unchanged and never rewrites mentions that carry a `validation_source`, because full-catalog re-writes every sweep churned the tables and overwrote reviewed decisions.
- `google-indexing-submit` stays a no-op (Indexing API is only for JobPosting/BroadcastEvent pages); discovery is sitemaps + internal links + IndexNow, and indexing is never inferred from a submission, HTTP 200 or missing impressions.
- Shared-person recommendation bridges, scores, explanations, episode person links, MCP person outputs and Person JSON-LD use only verified identities (`person_link_trusted_v1` / `get_shared_verified_people_v1` / `get_episode_person_links_v1`, client mirror `_shared/person-link-trust.ts`), never raw `people[]`/`mentioned[]` names, because homonyms were presented as the same person.
- Temporary quota/cadence raises go only through `start_pipeline_catchup_v1` / `extend_pipeline_catchup_v1` / `pipeline_catchup_tick_v1` (≤24 h, audited old/new values, restore only values still equal to the catch-up value; runner cadence overrides are honoured by queue-health-controller only while the catch-up is active), because hand-edited raises were forgotten or clobbered later owner changes and two cron writers flap.

- Agent search: `/kereses?q=` is prerendered for bots (worker `isAiAssistant` → `tier=ai`, else `basic`) as a noindex,follow episode list, and only internal callers holding `AGENT_SEARCH_KEY` (prerender, MCP `search_episodes`) lift the search-hybrid bot gate to the human search request; the worker caches search pages per query+tier with upstream Set-Cookie/Vary stripped, because AI assistants need visitor-quality results without indexed thin pages or per-hit AI spend.
- Paid scheduled edge functions that must not be startable from outside verify a per-job token from `internal_job_tokens` (service-role-only table, sent by the cron command as `x-internal-token`) or an admin JWT, because the anon key is public and cron calls carry no user session.
- Recommendation compatibility uses `public.recommendation_text_group` + `recommendation_is_compatible_v2` (similar_episodes, get_related_episodes_by_embedding, smart_player_discover incl. entity/chunk rails) mirrored in `src/lib/recommendationGuards.ts` (word-bounded patterns, science never bridges to esoteric/true-crime, cross-group needs a verified person/org or ≥2 shared topics), and recommendation RPCs never return `episode_chunks` text, because substring keywords and single generic tags paired physics with pseudoscience and chunks are private transcript text.
- Podcast similarity embeddings are written only by `embed-podcast-runner` from `_shared/podcast-embedding-content.ts` (public metadata, RSS episode titles, topic labels; versioned + content-hash re-check, backoff table), its cadence is owned solely by queue-health-controller, and `get_similar_podcasts_by_embedding` uses exact search plus `recommendation_is_compatible_v2` counting only distinctive (≤15% of podcasts) shared topics, because rank tokens in the input, an ivfflat single-list probe and ubiquitous labels produced off-topic neighbours.
- Organizations leave indexing/hub lists for quality only via `apply_org_quality_holds_v1` (two opinions, protected types exempt, CAS + `organization_quality_hold_log`, undo via `release_org_quality_holds_v1`), and `recompute_org_gated_counts` must honour `quality_hold_at`, because direct flag writes were undone by recounts and the cheap reviewer alone rejected real bands.
- `episode-topic-extractor` claims fresh (≤14 days) pending episodes before backlog, and one-time tier widenings/re-queues run only through `controls.catchup` (`_shared/topic-catchup.ts`, total cap counted from start, then base tiers for backlog; re-queues logged in `topic_retry_reset_log`), because backlog drains must not delay new episodes or exceed an owner cap.
- Episode vectors (`episode_embeddings`) are written only by `embed-episode-runner` from `_shared/episode-embedding-content.ts` (verified clean text, newest first, backoff, spend per pass); `pipeline-watchdog` alerts via `fresh_episode_coverage_v1` (only clean text settled ≥90 min, only embeddable texts), because a stopped runner reports nothing, while in-flight episodes raised false alarms.
- Podcast→publisher links come only from `refresh_podcast_publishers_v1` (feed header/domain/title evidence, no AI, manual rows kept) and org duplicates merge only via `merge_organization_into_v1` (logged, `undo_organization_merge_v1`, 301 via `resolve_org_redirect_v1`), because media outlets publish shows and duplicates must stay reversible.
